     1→     1→# Msaada — Project Worklog
     2→     2→
     3→     3→A hackathon MVP: CHV logs a home-visit observation → Qwen triage classification → stored (de-identified) → county-level aggregate dashboard.
     4→     4→
     5→     5→## Architecture (sandbox-adapted)
     6→     6→
     7→     7→The build spec calls for Supabase (Postgres + Auth + Realtime). This sandbox ships **Prisma + SQLite** and **z-ai-web-dev-sdk** (which exposes Qwen-family models server-side). We adapt faithfully:
     8→     8→
     9→     9→| Spec (Supabase) | Sandbox implementation | Notes |
    10→    10→|---|---|---|
    11→    11→| Postgres `triage_records` / `chv_users` | Prisma models on SQLite | `text[]` → JSON-encoded TEXT; `gen_random_uuid()` → cuid() |
    12→    12→| Supabase Auth (email/password) | Cookie-session demo auth (`src/lib/auth.ts`) | Scrypt-hashed passwords; documented swap path |
    13→    13→| Postgres RLS (`auth.uid() = submitted_by`) | Enforced in `src/lib/triage-store.ts` data-access layer | `insertTriageRecord` requires `submittedById`; dashboard queries are aggregate-only |
    14→    14→| Postgres VIEW exposing only aggregate counts | `getDashboardStats()` groupBy queries that NEVER select `observed_indicators` / `chp_next_action` / `confidence_note` text | De-identification at the data-access boundary, not just the app |
    15→    15→| Qwen chat completion API | `z-ai-web-dev-sdk` chat completions (server-side only) | `src/lib/qwen.ts` |
    16→    16→
    17→    17→## Routes
    18→    18→- `/` — CHV login + observation submission form + non-dismissable crisis panel
    19→    19→- `/dashboard` — county/daily/tag aggregate charts (Recharts), no auth for demo (TODO: county RBAC)
    20→    20→- `/api/triage` — POST; Qwen classify + de-identified DB write
    21→    21→- `/api/auth/signup`, `/api/auth/login`, `/api/auth/logout` — demo auth
    22→    22→- `/api/seed` — POST; seeds synthetic transcripts (1 crisis, 4-5 routine, 3-4 followup, 1 facility referral)
    23→    23→
    24→    24→## De-identification rule (hard constraint)
    25→    25→The CHV's raw free-text observation is **never persisted**. Only model-returned structured fields (classification, observed_indicators, aggregate_tag, chp_next_action, confidence_note, escalation) plus county/ward and the submitting CHV id are stored. The dashboard never reads indicator text.
